## Market truth (API vs MCP serving?)

- Skrun is skill-as-API: `POST /api/agents/{namespace}/{agent}/run`
  (`run.ts:1` `createRunRoutes`, `router.post("/agents/:namespace/:name/run")`;
  mounted in `index.ts:1` `app.route("/api", createRunRoutes(...))`) with
  `Authorization: Bearer <token>` + JSON body matching the `agent.yaml`
  input schema, typed JSON output back (tekai reference live).
- Contract layer is `agent.yaml` next to `SKILL.md`: model + fallback chain,
  typed `inputs`/`outputs`, `permissions`, `state` (kv/none + TTL), `tests`
  (tekai + `docs/agent-yaml.md` live listing). SKILL.md = what, agent.yaml = how.
- Three delivery modes on one route: sync JSON (default), SSE stream
  (`Accept: text/event-stream`), webhook fire-and-forget (`webhook_url` +
  202 + background `executeStream`; reference + `run.ts` SSE/WEBHOOK/SYNC blocks).
  Our MCP is the opposite: stdio `skill_search` only, search-only, no execution.
- MCP is consumed INSIDE the run, not served: `McpToolProvider` per
  `agentConfig.mcp_servers`, cached by config key (`mcpCache`, TTL 600s/max 20),
  plus `ScriptToolProvider` from the bundle `scripts/` dir (run.ts
  `buildToolRegistryForAdapter`; tekai Playwright example live).
- Trust shape we can steal as ideas: strict-semver `version` pin (omit = latest,
  `VERSION_NOT_FOUND` returns up to 10 recent versions), run-auth
  (public = any authed caller, private = owner/admin + 404-identical-to-absent),
  caller-key consent gate (`X-LLM-API-Key` + `X-LLM-Base-URL` origin check),
  secret redaction on errors/events, per-run namespaced state
  (`<namespace>/<slug>`), per-route rate limits + body caps (index.ts mounts).
- Verdict for R3: keep stdio MCP for local search; add ONE typed
  execution-shaped idea (contract + version pin + sync-only first) before any
  SSE/webhook. No cloud adapter, no dashboard, no billing.
