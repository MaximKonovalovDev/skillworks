## Market truth (how is their eval built?)

- 8 domain capabilities (logistics/retail/manufacturing/energy), each an
  Agent-Skills dir: `SKILL.md` (<500 lines) + `references/` (on-demand depth)
  + `evals/` (`scenarios.json` + `rubric.md` + `run_evals.py` + `results/`).
  201 scenarios total, avg 93.2% skill-equipped vs 81.4% bare model (+11.8pp).
- Two-stage pipeline (`shared/eval_framework.py`): Stage 1 subject agent gets
  full SKILL.md + all references as system context + scenario as user message
  (`generate_agent_response`); Stage 2 separate grader instance scores against
  weighted rubric criteria (`grade_response`), JSON-only output
  (`pass|partial|fail` + reasoning, scores 1.0/0.5/0.0).
- Each scenario: 3-5 criteria, weights sum to 1.0, specific pass/fail rubric
  text; scenario pass threshold `weighted_score >= 0.7`
  (`eval_framework.py: run_eval`); difficulty mix easy ~30 / medium ~40 /
  hard ~30; realism bar (dollar amounts, names, tiers, timelines).
- Baseline methodology (`docs/EVAL_METHODOLOGY.md`): skill run vs `--baseline`
  run with NO system prompt at all (raw scenario as user message); same model,
  scenarios, rubric, grader — only the system prompt changes. Results committed
  side by side: `eval_results.json/.md` + `baseline_results.json/.md`.
- Reports (`shared/scoring.py`): `aggregate_scores` (overall + by_difficulty +
  by_category + passed count) → `generate_json_report` + human
  `generate_markdown_report`. Interpretation bands: 85%+ expert, 70-84
  competent, 50-69 inconsistent, <50 insufficient.
- Honest-eval contrast with us: our gate is offline substring search over
  chunks (`book2skill/eval.py`, 0.6 refuse-export); theirs is model-graded
  domain judgment with a no-context baseline proving lift. We steal the
  SHAPE (weighted rubrics, baseline delta, dual reports, scenario schema),
  never the API calls.
