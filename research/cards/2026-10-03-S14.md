## Spec truth (what the reference says)

- Skill = directory with required `SKILL.md` + optional `scripts/` + `references/` +
  `assets/` (+ anything else). `SKILL.md` = YAML frontmatter + Markdown body.
- Frontmatter: `name` required 1-64 chars, lowercase a-z/0-9/hyphen only, no
  leading/trailing hyphen, no consecutive `--`, must match parent dir;
  `description` required 1-1024 chars, non-empty, what + when + keywords;
  `license` optional (name or bundled-file ref); `compatibility` optional 1-500
  chars (product/packages/network); `metadata` optional map str->str;
  `allowed-tools` optional space-separated string (experimental).
- Body: no format restrictions; recommended steps + I/O examples + edge cases;
  agent loads whole file on activation — split long content into referenced files.
- Progressive disclosure: metadata ~100 tokens (name+description at startup) →
  instructions <5000 tokens recommended (full SKILL.md on activation) → resources
  on demand; keep SKILL.md under 500 lines; one-level relative refs from skill root.
- Validation: `skills-ref validate ./my-skill` checks frontmatter + naming.
- Ours: `build._frontmatter` (build.py:26) emits `name/description/license: MIT`
  only, lowercases but never validates (allows `--`, leading/trailing `-`, >64,
  dir-mismatch, empty/short description); no `compatibility/metadata/allowed-tools`
  passthrough; body unbounded; scaffold is `chapters/notes.md + glossary.md +
  patterns.md + cheatsheet.md + references/sources.md` (no `scripts/`/`assets/`,
  no 500-line/5000-token budget, no one-level-ref rule); `audit.py` 18 lines counts
  tokens but enforces no spec rule.
