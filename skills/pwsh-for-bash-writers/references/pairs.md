# Tested pairs: bash habit and the pwsh form

Made from pairs.json. Do not edit this file by hand.
Every pair ran in pwsh 7 with Git's usr/bin off PATH. `bad` failed or gave a wrong answer. `good` printed the answer shown.

## Search text

### grep-line
bad (fails: not recognized):
```
grep -n TODO notes.txt
```
good:
```
Select-String -Path notes.txt -Pattern TODO
```
prints: `notes.txt:3:TODO gamma 3`
Or use the Grep tool. rg (ripgrep) is installed too: rg -n TODO notes.txt.

### rg-search
good:
```
rg -n TODO notes.txt
```
prints: `3:TODO gamma 3`
ripgrep is installed and fast. Put the pattern in single quotes: rg -n 'a|b' path. Select-String takes a regex too; add -SimpleMatch for plain text.

### grep-count
bad (fails: not recognized):
```
grep -c TODO notes.txt
```
good:
```
(Select-String -Path notes.txt -Pattern TODO).Count
```
prints: `2`

### grep-files
bad (fails: not recognized):
```
grep -rl TODO sub
```
good:
```
Select-String -Path sub/*.md -Pattern TODO -List | ForEach-Object Path
```
prints: `a.md`
Select-String expands the wildcard itself; for a whole tree pipe Get-ChildItem -Recurse -Filter *.md into it.

### grep-head-pipe
bad (fails: not recognized):
```
Get-Content notes.txt | grep TODO | head -n 1
```
good:
```
Get-Content notes.txt | Select-String TODO | Select-Object -First 1
```
prints: `TODO gamma 3`

node -e 'console.log("x".repeat(50))' | ForEach-Object { $_.Substring(0, [Math]::Min(10, $_.Length)) }

(Get-Content notes.txt) -replace 'TODO','DONE'

## Files and folders

### find-name
bad (fails: File not found):
```
find . -name '*.md'
```
good:
```
Get-ChildItem -Recurse -Filter *.md | ForEach-Object Name
```
prints: `a.md`
find is the old Windows find.exe, not the Unix one. Or use the Glob tool.

### which
bad (fails: not recognized):
```
which node
```
good:
```
(Get-Command node).Source
```
prints: `node`

### ls-flags
bad (fails: parameter):
```
ls -la
```
good:
```
Get-ChildItem -Force | ForEach-Object Name
```
prints: `notes.txt`
ls is an alias of Get-ChildItem: plain ls works, ls -la does not.

### touch
bad (fails: not recognized):
```
touch x.txt
```
good:
```
if (-not (Test-Path x.txt)) { New-Item -ItemType File x.txt | Out-Null }; Test-Path x.txt
```
prints: `True`

### rm-rf
bad (fails: parameter):
```
New-Item -ItemType Directory sub2 | Out-Null; rm -rf sub2
```
good:
```
New-Item -ItemType Directory sub2 | Out-Null; Remove-Item -Recurse -Force sub2; Test-Path sub2
```
prints: `False`

### test-file
bad (fails: Missing type name):
```
[ -f notes.txt ] && echo yes
```
good:
```
Test-Path -LiteralPath notes.txt -PathType Leaf
```
prints: `True`

### basename
bad (fails: not recognized):
```
basename sub/a.md
```
good:
```
Split-Path sub/a.md -Leaf
```
prints: `a.md`

### diff-files
bad (gives a wrong answer without an error):
```
diff notes.txt other.txt
```
good:
```
Compare-Object (Get-Content notes.txt) (Get-Content other.txt)
```
prints: `beta 9`
diff is an alias of Compare-Object: it compares the two names, not the file contents, and prints nothing useful.

## Time

### date-utc
bad (fails: ambiguous):
```
date -u +%Y-%m-%dT%H:%MZ
```
good:
```
Get-Date -AsUTC -Format 'yyyy-MM-ddTHH:mmZ'
```
Without date.exe on PATH, date turns into Get-Date and -u is ambiguous.

### utc-var
bad (fails: not recognized):
```
UTC=$(date -u +%FT%TZ); echo $UTC
```
good:
```
$utc = Get-Date -AsUTC -Format 'yyyy-MM-ddTHH:mmZ'; $utc
```

### time-cmd
bad (fails: not recognized):
```
time node --version
```
good:
```
$sw = [Diagnostics.Stopwatch]::StartNew(); node --version; 'seconds: ' + [math]::Round($sw.Elapsed.TotalSeconds, 1)
```
prints: `seconds:`
Measure-Command also works but it hides the command's output.

## Shell habits

### env-prefix
bad (fails: not recognized):
```
FOO=1 node -e 'console.log(process.env.FOO)'
```
good:
```
$env:FOO = '1'; node -e 'console.log(process.env.FOO)'
```
prints: `1`

### export
bad (fails: not recognized):
```
export FOO=1; echo $FOO
```
good:
```
$env:FOO = '1'; $env:FOO
```
prints: `1`

### for-loop
bad (fails: Missing opening):
```
for f in a b; do echo $f; done
```
good:
```
foreach ($f in 'a','b') { $f }
```
prints: `b`

### echo-e
bad (fails: ambiguous):
```
echo -e 'a\nb'
```
good:
```
"a`nb"
```
prints: `b`

### dev-null
bad (fails: dev):
```
node -e 'process.exit(3)' >/dev/null 2>&1; echo $LASTEXITCODE
```
good:
```
node -e 'process.exit(3)' *> $null; $LASTEXITCODE
```
prints: `3`
There is no /dev/null. Use $null. For stderr only: 2>$null.

### heredoc
bad (fails: Missing file specification):
```
cat <<EOF
hi
EOF
```
good:
```
@'
hi
'@
```
prints: `hi`
To write a file use the Write tool.

### python3
bad (fails: not recognized):
```
python3 --version
```
good:
```
python --version
```
prints: `Python 3`

### seq
bad (fails: not recognized):
```
seq 1 3
```
good:
```
1..3
```
prints: `3`

### xargs
bad (fails: not recognized):
```
Get-ChildItem sub -Name | xargs echo
```
good:
```
Get-ChildItem sub -Name | ForEach-Object { "file: $_" }
```
prints: `file: a.md`

### and-after-statement
bad (fails: Unexpected token '&&'):
```
foreach ($f in 'a','b') { $f } && echo after
```
good:
```
foreach ($f in 'a','b') { $f }; if ($?) { 'after' }
```
prints: `after`
&& and || work between two pipelines in pwsh 7, never after foreach, if, while or other statements.

### powershell-5
bad (fails: AsUTC):
```
powershell -NoProfile -Command "Get-Date -AsUTC"
```
good:
```
pwsh -NoProfile -Command "Get-Date -AsUTC"
```
powershell is Windows PowerShell 5.1 (no && or ||, no -AsUTC, UTF-16 on >). Always write pwsh.

### exe-with-space
bad (fails: not recognized):
```
.\my tools\hello.cmd
```
good:
```
& '.\my tools\hello.cmd'
```
prints: `hello from tools`
A path with a space needs quotes and the call operator &.

## Quotes and strings

### colon-in-string
bad (fails: Variable reference is not valid):
```
$name = 'x'; "$name: done"
```
good:
```
$name = 'x'; "${name}: done"
```
prints: `x: done`

### dollar-in-string
bad (gives a wrong answer without an error):
```
"price $450 now"
```
good:
```
'price $450 now'
```
prints: `price $450 now`
Inside double quotes $450 is a variable, so it prints nothing. Single quotes keep every character.

### member-in-string
bad (gives a wrong answer without an error):
```
$o = [pscustomobject]@{a=1}; "v=$o.a"
```
good:
```
$o = [pscustomobject]@{a=1}; "v=$($o.a)"
```
prints: `v=1`

### node-e-quotes
bad (fails: SyntaxError):
```
node -e "console.log(\"hi\")"
```
good:
```
node -e 'console.log("hi")'
```
prints: `hi`
A backslash does not escape a quote in pwsh. Put the script in single quotes, or write it to a .mjs file with the Write tool.

### nested-pwsh
bad (fails: not recognized):
```
pwsh -NoProfile -Command "$x = 5; Write-Output $x"
```
good:
```
pwsh -NoProfile -Command '$x = 5; Write-Output $x'
```
prints: `5`
The outer pwsh fills in $x before the inner one starts. Single quotes stop that.

### here-string-header
bad (fails: No characters are allowed):
```
Set-Content -LiteralPath h1.txt -Value @'# Title
body
'@; Get-Content h1.txt
```
good:
```
Set-Content -LiteralPath h1.txt -Value @'
# Title
body
'@; Get-Content h1.txt
```
prints: `# Title`
@' must end its line, and '@ must start its line.

## Paths

### wildcard-path
bad (fails: does not exist):
```
Get-Content -Path 'sub/[x]/g.txt'
```
good:
```
Get-Content -LiteralPath 'sub/[x]/g.txt'
```
prints: `hi`
-Path treats [ ] * ? as wildcards. Use -LiteralPath for any name you did not make yourself.

### git-bash-path
bad (fails: Cannot find path):
```
Get-Content /c/Windows/win.ini -TotalCount 1
```
good:
```
Get-Content C:/Windows/win.ini -TotalCount 1
```
/c/Users style paths are Git Bash only. pwsh wants C:/Users or C:\Users.

### native-glob
bad (fails: os error 123):
```
rg -n TODO sub/*.md
```
good:
```
rg -n TODO sub -g '*.md'
```
prints: `a.md`
pwsh does not expand * for programs. Cmdlets expand it, programs do not.

## Exit codes

### exit-code
good:
```
node -e 'process.exit(2)'; "exit=$LASTEXITCODE"
```
prints: `exit=2`
$LASTEXITCODE is the exit code of the last program. $? is only True or False.

### exit-code-pipe
good:
```
node -e 'process.exit(2)' 2>&1 | Select-Object -Last 3; "exit=$LASTEXITCODE"
```
prints: `exit=2`
Piping a program into a cmdlet keeps its exit code.

### native-no-stop
good:
```
$ErrorActionPreference = 'Stop'; node -e 'process.exit(1)'; 'still ran'
```
prints: `still ran`
A failing program never stops the script, even with ErrorActionPreference Stop. Test $LASTEXITCODE yourself.

### curl-exe
good:
```
(Get-Command curl.exe).Source
```
prints: `curl.exe`
Write curl.exe. In Windows PowerShell 5.1 plain curl is Invoke-WebRequest with other flags.
